# From public documentation to an engineering guide

Choose a bounded topic and audience. Retrieve official sources and record a dated claim ledger. Outline chapters in dependency order. Write original explanations with a clear separation between documented behavior, engineering recommendations and illustrative examples. Each chapter should solve a concrete problem, link its sources and close with actionable advice.

Review every factual claim against the fetched source. Preserve useful static content when adding interactive diagrams. Check route integrity, no-results states, keyboard operation, small screens and artifact exports. Update source dates only after actual review. Never infer private implementation from a public feature description.
